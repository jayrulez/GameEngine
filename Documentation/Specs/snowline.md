## Where it lives and how it is built

- **Project**: `Data/SampleProjects/Snowline` (its `Cooked/`, `.cache/`, `Editor/` and `Dist/`
  generated and ignored, as the other samples'). Authoring scripts in its `Tools/`, as
  PaperKid's: an MCP client, scene and prefab generators, and Blender scripts on the shared
  kit (`kit3d.py`, copied in).
- **Through the tools, not by hand.** Assets by `asset_create` / `asset_import` /
  `asset_data_write`, scenes by `scene_write`, components by `component_set`, scripts by
  `script_create` / `script_validate`, playtests by `pie_run`. A tool that is missing or wrong
  is a finding: fix it in the engine with a test, on its own commit, then carry on.
- **Terrain from a script.** The heightfield and its splatmap are generated by `Tools/terrain.py`
  (an r16 height image and a splat png along the course spline: the course carved as a run,
  banks and kickers shaped into it, trees kept off it) and imported with `asset_import`. There
  is no MCP sculpt brush, and a generator keeps the course and the terrain in step.

## Concept

Ride a snowboard down a mountain against the clock. Each course has three ghost riders, one per
medal, to beat; your own best run becomes a ghost too. The fun is the line you choose (flags to
pass, shortcuts through the trees, gems off the safe line), air (kickers, a grab, a clean
landing for a burst of speed) and a combo meter that pays for riding with style.

## Core loop (one course)

1. Start at the top gate; the HUD shows the time, the combo meter, gems and the medal pace.
   The medal ghosts set off with you.
2. Ride down: gravity drives you, the stick carves (a hard carve scrubs speed), a button
   crouches (tuck: faster, wider turns) and releases into a jump.
3. Slalom flags: pass each on its marked side; a miss adds 2 s.
4. Kickers and banks: in the air, hold the grab button for a grab (score grows with its length);
   land with the board along your path for a clean landing (a speed burst, combo up); land
   across it and you crash (a few seconds lost, combo gone).
5. Gems sit off the safe line; tree shortcuts are faster and narrower; near-misses past trees
   feed the combo.
6. Cross the finish: time plus penalties, the medal earned, score (gems, tricks, combo, time
   bonus), and the best run saved with its ghost.

## Courses and progression

| Course | Teaches | Features |
|---|---|---|
| Meadow | carving, flags, one kicker | open slope, sparse trees, wide gates |
| Forest | lines and shortcuts | dense vegetation, a shortcut, narrow gates, near-misses |
| Ridge | air | a run of kickers and a gap; an avalanche chases you down the last stretch |

A bronze unlocks the next course. Best times, medals and scores are saved; the title shows the
medals won. Crashes cost time, not lives (a time trial has no game over); the medals are the
stars. Ending: a short summary after a medal on Ridge.

## The engine it exercises

| Feature | How the game uses it | Today (2026-10-04) |
|---|---|---|
| Terrain (`terrain`) | the mountain; heightfield collider | creators and png/r16 import; cooked terrain loads in the player; no script height query |
| Vegetation (`terrainVegetation`) | snow-dusted pines and rocks; splat-driven grass on Meadow | procedural and prop layers set by `component_set`; no MCP scatter tool |
| Spline (`spline`, `path_follow`) | the course line: gates, gems, medal ghosts, the avalanche | `SceneSplines` samples by t and distance, closest point; points set by `component_set` |
| Animation graph (`animation_graph`) | the rider: carve blend, tuck, jump, grab, land, crash | graph source by `asset_data_write`; script sets parameters (`setFloat`/`setBool`/`setTrigger`) |
| Decals (`decal`) | board tracks in the snow, fading | a prefab spawned along the path |
| Physics joints (`physics.Joint`) | flags and fences on hinges that swing when hit | component exists; script has no joint API (not needed: they react to contact) |
| Particles, Save, UI, audio | snow spray, the avalanche, results, saves, wind | as in the other games |
| Blender kit | the rider, board, flags, gates, fences | `kit3d.py` |

**Web:** terrain and vegetation run in the browser on this engine (`Code/Samples/TerrainPlayground`),
from an in-memory heightfield. Not proven: a cooked terrain through the exported player, which
the first scene checks. On Sedulous they have never run in a browser, so this game's first
scene will be its first terrain web build: keep it small, and record numbers to compare.

## Engine gaps known before starting

Each is fixed in the engine with a test, on its own commit, when the phase that needs it
reaches it; the plan is checked against the code, not guessed.

1. **A board needs momentum on a slope.** A grounded character moves only by its input
   (gravity acts in the air), and script can read neither its velocity nor the ground's normal.
   The game needs the slope's normal under the rider and the rider's velocity, so the board
   script can integrate gravity along the slope, carve and brake. Shaped as reflected,
   scriptable properties on the character component (read-only `velocity` and `groundNormal`,
   and a full-velocity drive), not only facade functions, so Sedulous mirrors it as fields.
   Decided at P0 against what the character controller allows.
2. **A height or normal under a point**, for placing gems, gates and ghosts on the snow. A
   `rayCast` works today; a terrain query facade is the cleaner fix if the game needs many.
3. **The player's ghost does not fit Save.** Save holds typed scalars by key (int, float,
   bool, text). A ghost is a run sampled at 10 Hz (position, yaw and the rider's pose state per
   sample, interpolated on playback): about 600 samples for a 60 s run. Decided at P2 between
   (a) a list or blob value kind in the save format (a version change, in both engines), (b) the
   script encoding the ghost into one text value, and (c) a ghost file through a new script API.
   (a) or (b) preferred.
4. **Authoring by raw records**: spline points, vegetation layers and the animation graph go
   through `component_set` and `asset_data_write`. Acceptable for a generator script; if one
   is awkward or unsafe, that is a finding.

## Phases

- **P0 First scene, measured.** One short slope from `terrain.py`, one vegetation layer, the
  course spline, a placeholder rider sliding down it on the board script (gap 1 closed).
  Exported to web and the Deck. Self-contained, for Sedulous's first terrain web build, which
  reproduces it from the numbers below rather than approximating it. Targets: a 513 x 513
  heightfield at 1 m spacing (513 m square, heights 0 to 120 m), a 400 m course from the top
  gate to the finish, one procedural vegetation layer (pines) off the course. The values used
  are written into the table, adjusted if the importer or the terrain needs otherwise.
- **P1 Riding.** The board controller (gravity along the slope, carve, tuck, brake, jump), the
  chase camera, the Blender rider and board with their animation graph, track decals, snow
  spray, wind audio rising with speed. Playtested with `pie_run`.
- **P2 Meadow, complete.** Gates with jointed flags, gems, the finish, penalties, the HUD, the
  results screen, medal ghosts (`path_follow` along the spline at each medal's pace), saves of
  best times and the player's ghost.
- **P3 Tricks.** Kickers, air, the grab, landing judged against the path, the speed burst,
  crashes, near-misses, the combo meter and score.
- **P4 Forest and Ridge.** The shortcut, the avalanche, unlocks, the title's medals, the ending.
- **P5 Ship.** Audio (licences checked, kept beside the assets, credited), the README with
  screenshots, `Integration.Mcp` expectations, web and Deck exports, the demos site.
