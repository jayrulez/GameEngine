## Shader blocks: every one checked against its C++ mirror (2026-10-29)

The user asked for the values slotted into spare and borrowed lanes of the engine's shader blocks
to be cleaned up ("just slotting unrelated things in unused blocks"). An audit of every block
found 26 such places (the wind in PBR's spare material lanes, the clock in `IblParams.zw`, a faded
instance set's rank in the tint's alpha, its window in a different borrowed place per pass, a
probe "centre" that is an index, dead fields, a tonemap push that was a raw array calling a live
lane padding); `Specs/shader-blocks-cleanup.md` removes them in phases, and
`Specs/wind-for-every-shader.md` gives wind a block of its own, its parameters declared by the
effect (both approved). Phase 0, built: every engine block has a named mirror beside the pass that
fills it, with a size check, and `Integration.ShaderBlocks` compares each with the SPIR-V the
engine cook compiles, member by member (1802 checks), the material buffers against
`MaterialBuilder`'s offsets. No value uploaded changed.

Phase 1, built: a faded instanced set's window, its instance count and its pick id are a named
`InstanceSet` block beside its instances in all three passes, in place of the private copies of
each pass's view block it took per set (the window in `ShadowParams.zw`, `ShadowWind.yz`, and
`FadeStart` with `PickCamera.w`) and the rank in each instance's tint alpha; the rank is computed
from the instance's index, and the tint keeps its colour.

Phase 2a, built: the clock left its three borrowed lanes (`IblParams.zw`, `ShadowWind.x`,
`PickView.WindTime`) for a named `SceneTime` (and the forward view's `PrevSceneTime`) in each
pass's view block; the forward view's image-lighting dimmers are named fields beside it.

Phase 2b-1, built: an `effect` block (`effect Wind : WIND { ... (gate) }`) declares an effect's
parameters where its shader code is; every compile expands it in the includes it serves, from disk
or the editor's resolver alike, and the engine cook stores each effect's table in the shader pack
for the shader system to serve, so a game knows an effect's parameters without its sources.

Phase 2b-2, built: wind is the first effect. PBR, Phong, Unlit and every custom shader can sway (the
surface shaders and the low-level starter declare `WIND`); a material carries a Wind group bound in
its own set, which the factory gives it from the shader's declaration, with no C++ copy of the
effect's table; the 353 stored materials migrate on read (all had wind off); the renderer turns on
an effect's variant when its gate is above zero, knowing nothing of wind; scripts set
`Wind.Strength`. A GPU probe shows a PBR and a Phong card swaying with their shadows, on Vulkan and
WebGPU.

Phase 2b-3, built: the material page shows each effect group as a section of its own (Wind:
Strength, Speed, Height, with the effect's ranges), edited through its undo path; authoring gives a
material the groups its shader declares (2b-2 had only the runtime factory do it, so a new material
showed none); `material_set_shader` reports a material's effects; the MCP guide, the renderer doc
and the public docs' materials and custom shaders pages describe wind as an effect.

Phase 3, built: the per-draw `Object` block is one declaration (`object_block.hlsli`), every field
by its name, in the forward, depth and pick stages, where forward and depth called the pick ids
padding and two stages stopped short; the per-instance stream has a named layout per pass
(`GpuDrawOffsets`, `GpuPickDrawOffsets`), where one `DataOffsets` meant different things by pass,
and a MultiMesh set's pick draw binds a stream in the pick layout instead of the forward's. The
GPU pick probe now picks a MultiMesh set; a live set's InstanceSet buffer is freed at shutdown.

Phase 4, built: the forward view's probe "centre" (`ProbeCenter`, whose x was an index and w a
count) is `ProbeBase` and `ProbeCount`, its two dead box fields are gone, and each probe record names
its scalars where they rode the spare lane of each vector (intensity, blend distance, cube slice,
and the mip count, priority and parallax the C++ partly called padding).

Phase 5, built: the remaining passes name their values where they rode another value's lane: the
image-lighting push's sun intensity, sky rotation, turbidity and sun size (in the colours' alphas);
the sky's sun size, background intensity and sun intensity; terrain's shadow scalars, height-blend
contrast, splat parameters and flags (now uints), with the pick pass's block given a name of its
own; the decal's inverse target size and fade cosines; the particle and sprite instances' sizes,
rotation, mode, soft distance and stretch (the vertex layouts byte for byte as they were); the SSGI
resolve's sky dimmer.

Phase 6, built, which completes the cleanup on clang: last frame's jitter has a field of its own
beside this frame's (view, sky, terrain), the sky's Y sign and terrain's skirt depth are named, the
SSGI resolve declares the pads its C++ has, the forward view's shadow fade, shadow uv sign and debug
mode are named scalars, and each vector-graphics pipeline names what the shared vertex attributes
carry for it (the box shadow's operand and signed corner radius, a glyph's edge shift and ramp, a
layer's saturation and brightness), written through named constructors. The TAA history's alpha,
the previous depth, is documented where it is written and read.

P9 gives the viewer its preferences and recents: the settings file kept line by line (a line it

cache clear (the grid's pictures freed while drawn); the pictures now stay and their files are
drawn again.
P10a takes the model viewer's file reads off the main thread. Timing an open first showed where
the time goes: reading a large FBX is 60 to 170 ms in Debug, its cook and bind a few ms, so a
worker reads files while the main thread cooks and binds as before. A tab now opens at once and
says it is cooking; thumbnails read on a worker of their own, and the grid's line says how far
they have got ("drawing 418 of 1,106"). Over MCP the window answered within a frame throughout a
folder of 1,106 models.

the tabs discussion.
P11 closes the viewer's second phase with its exports: a collection as CSV (its path, each
model's name there, the file, tags, note), and Copy Files to Folder, which brings a game's models
out for its project, a subfolder per sub-collection, each model renamed to its name there and
taking along the images and glTF buffers it needs. A file already there and the same is passed
over; a different one is never overwritten, only reported. Both are commands
(`export_csv`, `export_copy_files`), in the Library menu and on a collection's right-click menu.
The GUI's fonts: SetFonts kept a replaced font service for two frames, on the reasoning that
every root restyles by then; a scene tier restyles only when its scene draws, so a game GUI not
drawn for a while could still hold the freed fonts (Sedulous found the crash on a game GUI's first
frame). The same fonts set again now keep their service (the editor sets them after every cook),
and a replaced one lives until the GUI goes.
The input map page's touch stick Radius row read in pixels (0 to 1000) while the runtime takes it
as a fraction of the screen; it now reads and bounds it as the region rows do (a Sedulous finding).
An import's name clashes, decided with the user for both engines (Sedulous ports this): an
importer reused any same-named asset whatever its type, and every import copied to
Sources/<file name>, so a second `a.png` from another folder took over the first's asset and
overwrote its source. Now a name held by another type is always refused; one held by another
file's asset of its type is a clash the editor's import window asks about (Replace or Keep both)
and an agent's import refuses unless `onConflict` says; re-importing the same file replaces in
place, as before. Telling the two apart, the project keeps an import ledger in its ignored .cache/
(the OS file each Sources file came from; never in the project, so no machine's paths are
published), and a copy never overwrites another file's ("a.2.png"). The eleven single-asset
importers share one claim (ClaimSingleAsset); a model claims its folder the same way.
