# i18n - the foundation layer

**Status:** revised for review, 2026-10-17. Not implemented: no code has landed (the August
roadmap's "shipped" was this spec, not a library). Replaces the August draft (v2), keeping its
rulings and adding what the GUI lab's translation (`gui-lab-evolution.md`, E9) needs today.

## What it is

`foundation.i18n` (`Code/Foundation/I18N`, alias `Foundation::I18N`) holds a game's and the
editor's text in several languages and answers "this key, in the current language": string
tables, a resolver that merges them with a fallback chain, positional formatting, plural forms,
and pseudolocalization. The tables describe each language whole: its texts, how it counts (its
plural rule) and which way it is written. The library itself knows no language: it evaluates what
the tables say. It depends on `foundation.core` alone: no resource, RHI, UI or messaging, so
every part is testable headless.

It is state and pure functions, so it is no subsystem: no per-frame update, no device, no scene
hook. Whoever needs text owns a `Localization`: the editor one for its own strings, a game host
one for the game's, a test one on the stack. Two in one process (the editor and an embedded game)
is a feature.

Reference: Traktor's `I18N` (dictionaries merged over a master, Text and Format); Godot for plural
forms, the fallback chain and pseudolocalization; eepp and ezEngine for reporting missing keys.
Sedulous has none (checked 2026-10-17).

## Keys

Keys are dotted ids (`menu.play`, `inventory.empty`) in one flat namespace: stable while the
wording changes, explicit where the same words mean two things (`door.open`, `file.open`), short
for long texts, and the shape a writers' string table takes. The development language is a column
like any other, not the key. A key without its text resolves to the key itself (below), so a gap
shows on screen.

## Types

### StringTable

The authored unit, one resource holding everything about its languages: locale columns over keys,
and each locale's own description.

- **Locales.** An ordered list of locale ids (`en`, `de`, `pt-BR`), each with:
  - its plural rule (below): for each category it uses but `other`, a condition in CLDR's rule
    syntax (`one: n = 1`; Russian's `one: n % 10 = 1 and n % 100 != 11`, `few: ...`), so the rule
    travels with the translations that depend on it;
  - its direction, left to right or right to left (`IsRightToLeft`);
  - either may be left unset, for a table that only adds texts to a locale another table
    describes.
- **Entries.** Per key, in each locale, a cell: missing, a text (UTF-8), or a plural entry (a text
  for each category the locale's rule uses, `other` always among them). A key is plain or plural
  in all its locales. Keys are hashed for lookup (a string and a hash map; not the type registry's
  hash domains, which are for type identity).
- A cell may be missing (a column translated in part); `HasText(key, locale)` says so, and for a
  plural entry `MissingForms(key, locale)` names the categories its locale's rule uses that it
  lacks, for tooling that reports completeness. An empty string is a translation, unlike a missing
  cell.
- Mutable (Set, SetPlural, Remove, RenameKey, AddLocale, RemoveLocale, SetPluralRule,
  SetRightToLeft): the editor's grid and an import change this type directly; nothing in a table
  is the runtime's alone.
- Serializable through `ISerializer`, versioned by the strict-versioning rule: the same body is an
  asset's source and, later, the cooked product. Other formats (CSV from a spreadsheet or a
  translator's tool) are converted to it in the pipeline layer, never read here.

### Localization

The resolver its owner holds: it borrows tables, holds the language, and answers.

- `AddTable(const StringTable*)` and `RemoveTable`: borrowed, not owned (the owner manages the
  tables' lives; the resource wrapper of a follow-up keeps references and feeds the raw tables
  in). The last table added wins for a key, so a patch or a downloaded table can override a base
  one. Keys defined twice are a tooling warning, not a runtime one.
- `SetLanguage(locale)` and `Language()`; `SetFallbackLanguage(locale)` (default `en`). An unknown
  language is allowed: resolution falls through the chain.
- **Resolution** of `Text(key)`: the language, then its parents (`pt-BR`, then `pt`), then the
  fallback language, then its parents, then a miss. A plural entry's `Text` is its `other` form.
- **A locale's description** merges as its keys do: the last table that sets a locale's plural
  rule, or its direction, wins. `IsRightToLeft()` is the current language's (through its parents;
  left to right when no table says), and `IsRightToLeft(locale)` any locale's.
- **A miss returns the key itself**, logged once per key (deduplicated by the key's hash): visible,
  findable, and gone once the text lands. `Has(key)` for a caller that must know. Callers do not
  pass default texts (they drift from the tables and hide gaps).
- **Missing keys are kept** (`MissingKeys()`, `ClearMissingKeys()`): each key asked for and not
  found, with the language it was asked in, in first-asked order, so a tool can write the gaps
  out for translators to fill (eepp's harvest) without scraping logs.
- `Text(key)` returns a view into a table's storage, valid until that table changes or is removed
  (a caller that keeps it copies; documented). Pseudolocalized text is formatted into a buffer the
  resolver owns, valid until the next call; `TextString(key)` returns a copy for callers that keep
  text.
- **Change notification** is a plain callback list, `u32 OnChanged(Function<void()>)` and
  `RemoveOnChanged(u32)`: no message bus, so the library stays a leaf. It fires on a language
  change, a table added or removed, and a pseudolocalization change. A consumer with a bus (a game
  host) bridges it to a `languageChanged` event; the GUI lab re-resolves its translated text.

### Formatting

`Format(key, args) -> String`: the text, then positional placeholders `{0}`, `{1}`. Positional,
because translations reorder arguments, which `core::Format`'s sequential `{}` cannot express.

- Arguments are a `Span<const Variant>` of the plain types (bool, the integers, f32 and f64,
  String and StringView); numbers print through core's formatting with a full stop for decimals
  (numbers by locale are deferred).
- `{{` and `}}` are literal braces. A placeholder naming a missing argument prints as written
  (`{3}` stays visible, as a missing key does).
- Formatting a missing key formats the key.

### Plural forms

`Plural(key, n)` and `FormatPlural(key, n, args)`: the text for count `n`, from the key's form for
the plural category of `n` in the language whose text was found (a fallback's text counts by the
fallback's rule), else its `other` form, else the key itself; `FormatPlural` then fills the
placeholders, `{0}` conventionally the count. `Plural` on a plain key is its text.

- `PluralCategoryOf(locale, n) -> PluralCategory` (Zero, One, Two, Few, Many, Other): the locale's
  rule from the tables, its conditions tried in CLDR's category order and the first that holds
  chosen, else Other. A locale no table gives a rule counts everything as Other, said once in the
  log, so its plural texts show their general form rather than a wrong one.
- The rule language is CLDR's for integer counts: the operand `n` (and `i`, the same for
  integers), `%` (modulo), `=` and `!=` against a value, a range (`2..4`) or a list of them
  (`2..4, 22..24`), `and`, `or` (`and` binding tighter). A rule that does not parse is refused when
  set, with its position, never at a count.
- The library holds no rules of its own: a table adding a language carries its rule, as gettext
  catalogs carry their Plural-Forms. The tests use English's (`one: n = 1`) and Japanese's (none:
  other only); adding French or Russian later is data.
- Only integer counts; fractions (CLDR's `v`, `f`, `t`) and ordinals ("1st") are deferred.

### Pseudolocalization

`SetPseudolocalization(PseudoOptions)` on a `Localization`, off by default: every text it resolves
(a miss included) comes back transformed, so text the code never sends through it, and layouts
that cannot take longer text, show at once.

- Options (each on or off): accented letters (`Settings` to `Šéţţîñĝš`, still readable; only
  look-alikes in Latin-1 and Latin Extended-A, which a font baked for European languages holds,
  so b, f, m, q, v and x stay as they are),
  lengthening by a share (30% by default, padded with `~`, as German and Finnish run long),
  brackets around each text (`[` and `]`, so a cut-off end shows), and a mirrored direction
  (the text wrapped in right-to-left marks, to try a right-to-left layout with readable text).
- Placeholders (`{0}`) and markup a consumer names as untouchable (the GUI lab's `[b]` rich-text
  tags, `{{binding}}`) pass through unchanged.
- A "show keys" option returns each key beside its text (`menu.play: Play`), for finding where a
  string comes from on screen.

### Locales

Free functions over BCP 47 shaped ids, with no database of locales:

- `ParentLocale("pt-BR")` is `pt` (empty when there is none); `NormalizeLocale` lowercases the
  language and keeps the region as written, so `en-US` and `en_us` compare equal.
- `IsLocaleShaped` accepts `xx`, `xxx`, `xx-YY`, `xx-Yyyy` (a script) and `xx-Yyyy-YY`; it checks
  the shape, never whether the language exists.
- Which way a language is written is the tables' to say (a locale's direction, above), as its
  plural rule is: the library keeps no list of languages.

## Consumers today

- **The GUI lab (E9a and E9b).** The host owns a `Localization` and gives it to the lab's context
  through the lab's translator interface (a thin adapter, in the lab). Markup's `text="@menu.play"`
  resolves through it; a binding's template is formatted with `Format` and `FormatPlural`; the
  lab re-resolves on `OnChanged`; its default direction is the `Localization`'s `IsRightToLeft()`;
  its
  sandbox loads serialized tables from its data folder (or builds them in code) until the
  pipeline converts other formats.
- **Later:** the game host and its scripts, and the editor's own strings (follow-up 2).

## Not in this layer (follow-up specs, in order)

1. **Resource and pipeline:** `foundation.i18n.resource` (the cooked table and its factory),
   `I18N.Pipeline` (a string table asset, its builder, CSV converted to the table and back for
   spreadsheets and translators' tools, duplicate-key warnings).
2. **Integration:** who owns the `Localization` in the game host and the editor, the script
   surface, a `languageChanged` event, project and editor language settings, and how the
   editor's own strings take keys (Traktor's way).
3. **Fonts:** a bake option taking its character set from the tables (for CJK).
4. **Deferred until a game needs them:** numbers, dates and currency by locale, gender, ordinals.

## Tests (with the library)

- StringTable: set and get per locale; missing cell against empty string; a plural entry's forms
  and MissingForms against its locale's rule; a key plain in one locale refused as plural in
  another; rename (all forms with it) and remove a key; add and remove a locale; a locale's rule
  and direction set, unset and refused when the rule does not parse; serialization round trip
  (texts, plural entries, rules, directions) and its version gate.
- Localization: a hit; a miss returns the key, logs once, and is kept in MissingKeys; each hop of
  `pt-BR`, `pt`, the fallback, its parent, the key; the last table wins, and removing it uncovers
  the one below; a language change, a table added or removed and a pseudolocalization change call
  back, and a removed token does not.
- Format: each argument type; reordered placeholders (`{1} ... {0}`); escaped braces; a missing
  argument prints as written; a missing key formats the key.
- Plurals: rules parsed and evaluated at edge counts (English's `n = 1` at 0, 1, 2; a modulo rule
  with ranges and `or`, Russian's, at 1, 2, 5, 11, 21, 22, 25, as data in the test); a locale with
  no rule counts all as other, logged once; the last table's rule for a locale wins; a missing
  category falls to `other`, a missing `other` to the key; the rule follows the language the text
  came from; `Text` on a plural key is its `other`.
- Direction: a locale's direction from its table, through its parents (`ar-EG` from `ar`), the
  last table's winning, left to right when none says.
- Pseudolocalization: accents, lengthening and brackets, placeholders and named markup untouched,
  show keys, a miss transformed too.
- Locales: the parent chain, normalization, shapes accepted and refused.
