## The asset browser's tree indents as the entity tree does (2026-10-10)

From the 0.1 backlog (user 2026-10-09): in the Assets panel's folder tree the space before each
level's chevron shrank the deeper the level, where the scene's entity hierarchy keeps it even.
The tree draws each chevron in its level's column, `IndentWidth` (20 px) wide, and a row's text
belongs one column further, `TreeView::ContentInset(depth)`; the entity hierarchy takes its text
offset from that, but the assets tree wrote a literal `(depth + 1) * 18`, so its text fell 2 px
further behind its chevron at every level. It now takes `ContentInset(depth)` too.

Test: `Editor.App.Tests` AssetsViewTests, a scratch project four groups deep, binds a tree row
at each depth and checks its text offset against `ContentInset`; with the old literal back, all
four depths fail. Clang and gcc green on Editor.App.Tests.

## List / Grid as icon toggles, and a grid view in the asset picker (2026-10-10)

From the 0.1 backlog (user 2026-10-09): the asset browser's List / Grid buttons were text; they
are icon toggles now (a list icon and a grid icon, the words as their tooltips). User, on the way:
"The asset picker dialog likely has the same issue, or maybe it doesn't have a grid view ... if it
doesn't have a grid view then close that gap too." It had only a list, so it has a grid now too.

- `ViewModeToggles` (Editor.App): the pair both views use, two `ToggleButton`s holding the new
  `EditorIcons` `viewList` and `viewGrid` glyphs (the existing `grid` icon is the scene's debug
  grid lines). A radio pair by the checked state, not the click: a toggle flips on a click and on
  Space alike, and the old buttons left neither checked when the checked one was clicked. The
  re-check is silent, since a property ignores a `SetValue` from its own Changed handler.
- The asset picker: the toggles beside its filter; a grid of tiles (a 48 px thumbnail over the
  name, the path and type as the tile's tooltip) over the same rows as the list; a double-click,
  Select and the right-click menu work from either view. Its choice is kept per project apart
  from the browser's (`EditorAssetBrowserSettings.pickerGridMode`, appended so settings saved
  before it still load).

Tests (`Editor.App.Tests` AssetsViewTests): the pair's icons and tooltips, the radio behaviour
and `SetGridMode` not reporting back; the browser's Grid toggle showing the grid and saving it;
the picker's grid offering the same rows, a double-click on a tile picking its asset, and the next
picker opening in the grid. Clang and gcc green on Editor.App.Tests (63 cases).

Also queued in `backlog-0.1.md`: a component picker dialog in place of the Add Component menu,
