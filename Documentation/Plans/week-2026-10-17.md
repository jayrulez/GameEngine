**Where play in editor lives** (the item asked for a decision): in Editor.Play, a library of its
own, since it runs a project rather than editing a scene or an asset. It builds on Editor.Scene
(a Game tab captures its viewport as a scene page does) and plugs in through the context's
existing `GamePageFactory`; `RegisterPlayInEditor` sets that and contributes the PIE tools, so
Editor.Scene no longer depends on play in editor and `RegisterSceneEditor` no longer takes the
embedded application. entity_inspect's `pie` reads a running game through a narrower service the
scene module owns, `IGameScenePage` (the tab's id, whether it runs, its scene), which
IPieInstancePage builds on; the editor's MCP tools are unchanged.

Editor.Scene keeps what scenes share: the settings rows (the profile page uses them, so
Editor.Render builds on Editor.Scene as Editor.Play does), the profile model, loading and framing
a project scene, the viewport capture, and the asset thumbnails, which share one preview stage
(the mesh, material, skeleton, model and particle thumbnails stay with it). The other new
libraries need nothing of Editor.Scene. `PrettifyPropertyName`, which the inspector and the
material page share, moved to Editor.App beside `ResourceRefEditor`. The moved pages now import
what they name (the fonts, the settings store) instead of reaching it through `editor.scene`.

## Transforms as CSS writes them, animation events, var() in drawables (2026-10-18)

Three of the survey's leftovers the user chose to do now (after "which are worth doing now?"):

- **Transforms in written order** (9f80934ac): a sheet's `transform` applied translate, rotate,
  then scale whatever order it wrote them in, and pivoted only about the view's own origin. It is
  now a list of functions (translate, scale, rotate, skew and their X and Y forms; a translate's
  percent is of the view) composed as CSS composes them into one 2D matrix, `Transform2D` (the GUI
  lab's form), about `transform-origin`. Views draw, hit-test, map and round through that one
  matrix. Transitions go function by function, pad `none` with identities, and otherwise mix the
  decomposed matrices the short way.
- **Animation events** (2d32964c0): a view raises `OnAnimationEnd` and `OnAnimationIteration` with
  the @keyframes' name, through the mutation queue after the frame's tick, and every script handle
  takes `onAnimationEnd` and `onAnimationIteration` (a `UiAnimationHandler` taking the name), so a
  screen can chain a slide-in or remove a faded toast. `game-ui.md` documents them.
- **var() in drawables** (d38ccffa6): `rounded-rect`'s fill and border, `color()` and gradient stops may be
  `var(--name[, fallback])`, resolved against the custom properties of the view being drawn, so one
  rule's background takes each view's accent and a theme switch reaches backgrounds. Lengths in a
  drawable, a side's own colour and state-rounded's derived states stay literal (backlog).

## Fixes the first Windows drops and the gcc lane found (2026-10-18)

Found as the week's builds went out, each with its test:

- **A Vulkan laptop that would not start** (5fd0fd186): on a two-GPU machine the editor died at
  startup ("ICD associated with VkPhysicalDevice does not support
  GetPhysicalDeviceCalibrateableTimeDomainsKHR"). The calibration query asked the loader for the
  KHR entry point first, which the loader answers whatever the device supports; it now uses the
  name the device advertised.
- **A Windows editor drop that could not create its device** (045228ddd): `CreateGraphicsDevice`
  had no fallback, so a build without the Vulkan SDK defaulted to a backend it did not contain and
  exited. It now falls back to a backend that is compiled in, and CI stops shipping Windows
  artifacts built without Vulkan.
- **A cook race** (d7f57a39c): every font build installed HarfBuzz into the shaper factory while
  other job workers read it, which crashed the Windows shared-library CI cooking PaperKid's fonts.
  The builder installs once, when it is made. That commit carried eight file moves of the
  Editor.Scene split by mistake; 0e2f8ed7e put them back.
- **Builds**: pseudolocalization's direction marks written as UTF-8 code units, which MSVC and gcc
  both refused as raw characters and then as `\x` escapes (b2411ec5c, d2312c2cb); the web build
  configures and compiles again (155c735c6); test fixes in VG.Renderer.Tests, VG.Backend.Tests,
  UI.Tests and Shell.Null.Tests (a82d8b498, f931df0a8, 2ca0962fe, 8814cb02e, ee4ab1ce9).
- **Text input kinds** (b2e1b288f): a password field took text input like any other, so the

## A binary read stops at the end of its data (2026-10-19)

Opening Snowline in the editor held it for over a minute per scene, longer on Windows. Its cooked
scripts predated the replicated flag (c5713bf63) but kept data version 0, so the editor read them
in the new layout and trusted a garbage count, reserving it and reading nothing millions of times.

- A count or a string length the bytes left cannot hold fails at once, an Array stops at its first
  failed element, and a failed reader reads nothing more (49ef68919); a framed region's length is
  checked the same way, so garbage no longer allocates up to 4 GB (e32619bf3, found while porting
  the bounds to the mirror).
- A payload of another data version is refused unread (f3199172a), and `ScriptClassSource` carries
  data version 1, so the older records are refused and recooked (e00f23ef7).
- `ReadObject` reads through a 64 KB buffer instead of a system call per field (aaa6c10b7).

## The script check compiles without running (2026-10-22)

Checking a script as it is typed needs a compile that runs nothing: AngelScript's build runs the
global initializers and Load then calls `main()`, and Luau's Load runs the chunk's top level, so a
half-written loop would hang the host. The user chose a compile-only check in the Foundation
script interface. `IScriptManager::Check` compiles against the registered surface and reports
errors with a column, in both backends (1b61744f7); `IScriptLanguageCook::Check` is what the
editor's Script page now validates with (44d6ffc92). MCP's `script_validate` still goes through the
cook. Also on master: a mouse event carries the modifiers held (9b945174c).
