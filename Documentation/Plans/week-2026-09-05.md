## DONE: ModelBone local matrix convention + glTF matrix-only nodes (2026-09-06)

An external agent's report (verified): ModelBone::updateLocalTransform built
its matrix in the COLUMN-vector convention (translation in the last column,
T * (R * S)) while the engine is row-vector everywhere (Translation writes
the last row, TransformPoint reads it, Transform::ToMatrix = Scale *
Rotation + last-row position). Never showed because NOTHING reads the bone
matrix: the cook and ModelResource carry the TRS fields. What the report
missed: glTF nodes authored with a `matrix` (not TRS) memcpy'd it into that
dead field and left the fields at identity -> those nodes COOKED AT THE
ORIGIN (real data loss).

Fix: the builder is `Transform{t, r, s}.ToMatrix()`; the glTF matrix path
decomposes with Transform::FromMatrix into the fields, then derives the
matrix. FBX audited: its convertMatrix transposes ufbx columns into rows
(correct) and inverse bind matrices go through it; TRS was already
populated there. Tests: Model.Tests pins (1,0,0)->(12,0,0) (old builder:
(2,0,0), proven by running the test against the stashed code) plus an
independent S*R-vs-R*S check via RotateVector (reviewer feedback: the first
cut compared the builder to its own implementation); NEW Model.GLTF.Tests
(matrix-only node lands in the TRS fields and matches the TRS node).
Battery is 151 suites again. Gate: clang, gcc, clang-shared, ASAN.

## DONE: Vulkan queue-family rules - three Beef-port findings (2026-09-07)

From the Beef port's MultiQueue run, all verified in Raptor:
1. SampleApp never requested a compute queue (DeviceDesc defaults
   computeQueueCount = 0), so Sample017 always took the single-queue fallback.
   Now asks for one; the device clamps to what the adapter has.
2. The barrier helper mapped ShaderRead/ShaderWrite to ALL_GRAPHICS |
   COMPUTE_SHADER regardless of queue - invalid on a compute-only (or
   transfer-only) family. New maskStagesForQueue(stages, QueueType) cuts a

the stage cut is pinned as a pure function; a device created with
